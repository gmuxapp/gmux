## v2.1.0 - 2026-09-01

### Highlights

**Task families**
Sessions now form families: agents, subagents, and process children share a redesigned sidebar and family panel with state filters and bulk mark-read/stop/interrupt actions. `gmux promote` makes a child a structural root, `gmux reparent` moves it, and per-root depth budgets bound recursive swarms ([#453](https://github.com/gmuxapp/gmux/pull/453), [#464](https://github.com/gmuxapp/gmux/pull/464), [#485](https://github.com/gmuxapp/gmux/pull/485), [#492](https://github.com/gmuxapp/gmux/pull/492), [#505](https://github.com/gmuxapp/gmux/pull/505)).

**Attention that behaves**
Unread attention is separate from durable error outcomes, child completions follow their direct parent, and successful supervised process exits mark themselves read. Less notification archaeology ([#472](https://github.com/gmuxapp/gmux/pull/472), [#499](https://github.com/gmuxapp/gmux/pull/499), [#511](https://github.com/gmuxapp/gmux/pull/511)).

**Terminal fidelity**
Session switches and reconnects preserve colors, normal/alternate buffers, cursor position, scroll margins, and soft-wrap provenance. Scroll anchoring holds your place during streaming output, and mobile Shift composes with Tab ([#484](https://github.com/gmuxapp/gmux/pull/484), [#500](https://github.com/gmuxapp/gmux/pull/500), [#503](https://github.com/gmuxapp/gmux/pull/503), [#510](https://github.com/gmuxapp/gmux/pull/510)).

**Performance at scale**
Conversation indexing moves behind daemon availability: in the merged 3,000-conversation benchmark, first health improved from 4.15s to 0.06s. Broadcast bursts are coalesced, and indexed, incremental projections cut a re-encoded one-row update at 10,000 sessions from about 100ms to 24ms ([#512](https://github.com/gmuxapp/gmux/pull/512), [#517](https://github.com/gmuxapp/gmux/pull/517), [#518](https://github.com/gmuxapp/gmux/pull/518), [#519](https://github.com/gmuxapp/gmux/pull/519)).

**Multi-host**
Peer bootstrap is bounded and atomic; shared cross-tailnet Tailscale hosts connect directly, and omitted remote rows are visible instead of silently disappearing. `/v1/health` now reports `conversation_index` and `session_recovery` progress ([#477](https://github.com/gmuxapp/gmux/pull/477), [#494](https://github.com/gmuxapp/gmux/pull/494), [#513](https://github.com/gmuxapp/gmux/pull/513), [#521](https://github.com/gmuxapp/gmux/pull/521)).

**ntfy notifications (Experimental)**
The owning daemon can send best-effort ntfy pushes after gmux's notification grace and presence checks, without including prompts, output, commands, paths, or session titles ([#483](https://github.com/gmuxapp/gmux/pull/483)).

### Upgrade notes

- Pending data on launcher stdin (for example, `foo | gmux -- cmd`) now causes a hard usage-error exit before session creation. Managed commands do not inherit launcher stdin; use `</dev/null` when no input is intended or `gmux send` to provide input.
- First 2.1 startup applies state-store migrations 00002–00005 and keeps an automatic owner-only pre-migration backup. Downgrading after 00005 is lossy because 2.0 cannot restore promoted-family structure; use that backup to roll back.
- The unversioned protocol-2 session snapshot stream is deprecated and available for 2.1 only. Custom consumers must request `session_stream=3` before protocol 2 is removed in the next release.

### Behavior changes

- Successful supervised process exits are automatically marked read when the direct parent has a live local runner; failures, interruptions, and unsupervised exits remain unread ([#511](https://github.com/gmuxapp/gmux/pull/511)).
- Family relationships use `gmux promote` and `gmux reparent`; promotion is structural. The Experimental `agent.max_subagents_by_depth` setting defaults to `[-1, 8]`.
- ntfy notifications require the ntfy app or a push-capable browser. With [`[notifications.ntfy]`](/reference/host-toml/#notificationsntfy), treat topics on public servers as secrets and keep `host.toml` owner-only (`0600` or stricter).

### Improvements

- Source and contributor builds use the exact Go 1.26.1 toolchain ([#520](https://github.com/gmuxapp/gmux/pull/520)).

## v2.0.0 - 2026-07-31

The biggest release yet, and the first with breaking changes. 2.0 makes agent status authoritative, hardens multi-machine access, moves the CLI to a stable verb-first grammar, and ships a rebuilt web app. A few things moved, so read the **[Migrating to 2.0 guide](https://gmux.app/migrating-to-2/)** before updating a fleet. Your agent can help migrate your projects and sidebar items if you'd prefer not to start with a clean slate.

### Agents can now orchestrate other agents

The new machine-oriented `gmux agent` surface launches, prompts, observes, and cancels subagents without scraping terminal output. `gmux agent prompt --new --no-wait` returns an addressable session once the prompt is admitted, without waiting for the turn to finish; `gmux wait <id>...` waits on several agents concurrently and prints source-attributed exchange reports in argument order. Stable exit codes and delivery errors distinguish completed work, agent failure, interruption, timeout, safe retry, and indeterminate delivery — enough structure to build reliable agent swarms from shell scripts and other tools. See **[Orchestrating agents](https://gmux.app/orchestrating-agents/)** for the complete workflow.

### A rebuilt web app

- **Home is an activity dashboard** — live sessions ordered by recent output and grouped by calendar day; project and host management moved into a proper **Settings** modal.
- **Mobile, seriously reworked** — new key row (arm-and-highlight ctrl/alt, always-present arrows and word-jump), copy/paste including images, long-press links to copy or open, and fixed reconnect storms on flaky data.
- **Find in terminal** (Cmd/Ctrl+F), **error toasts** for failures that used to be silent, and rendering fixes (WebGL artifacts, GPU context loss, scrollbars, stale-tab auto-reload).

### Verb-first CLI

`gmux -- <cmd>` to run, `gmux open` for the UI, and `ls` / `attach` / `tail` / `send` / `wait` / `kill` / `edit` as verbs. The old flags and bare-command shorthand are gone, but every removed form prints its exact replacement. If you had aliases defined, you'll need to change them: `alias gm='gmux --'`; `alias pi='gmux -- pi'`

### Multi-machine, locked down

Being on your tailnet now only lets a machine *reach* a host; the host's token authorizes it. Autodiscovery is replaced by explicit, token-authenticated hosts (`gmux auth` → **Settings → Hosts → Connect to host**), and cookie-authed requests are same-origin enforced. The 2.0 state store starts clean: re-add hosts, then add wanted peer projects under **Settings → Projects → From other hosts**.

### Agents report their own state

pi, Claude Code, and Codex no longer have their status guessed from terminal output. A small hook in each launch lets the agent report its conversation, turn boundaries, and title directly — so working/idle, unread, and session names are exact, not inferred. Opt out with `GMUX_NO_AGENT_HOOK=1`. (Codex live status needs Codex CLI ≥ 0.135.0.)

### One state store

All daemon state — sessions, projects, hosts, read/unread — now lives in a single SQLite database instead of scattered JSON files (ADR 0026). State changes are transactional, so nothing resurrects or goes stale after a restart, and the API always reflects your last write. New `gmuxd state check | backup | export` commands cover integrity checks, backups (backups contain host tokens — treat them as secrets), and redacted exports for bug reports.

### `gmux edit`

Managed editor tabs that work as `$EDITOR` — `git commit` inside a session opens a real gmux tab and blocks until you're done. Currently opens in a terminal, UI coming in a followup release.

### Under the hood

The daemon↔browser protocol moved to coalesced snapshots, adapters own their conversation discovery, peering runs on shared `sseclient`/`apiclient` packages, and a terminology cleanup landed (`kind` → `adapter`, session files → conversation files). Runner sockets moved off `/tmp` so they survive logout.

### Upgrade notes

Upgrade every machine (and rebuild devcontainers) together — 2.0 can't peer with 1.x. The state store starts fresh: running sessions keep running, but dead-session history, sidebar projects, and connected hosts don't carry over — re-add hosts and projects after upgrading. Scripts parsing `gmux ls --json`: `kind` → `adapter`. Full details in the **[migration guide](https://gmux.app/migrating-to-2/)**.

## v1.0.0

Prefix any command with `gmux` and it shows up in a live browser dashboard. Watch what every agent is doing, steer them from your phone, and aggregate sessions from every machine, container, and VM into one place.

This release stabilizes the core and adds multi-machine support.

### Multi-machine sessions

gmux now aggregates sessions across machines. Pick one gmuxd as your dashboard (the hub), and it connects outward to other instances (spokes) to merge their sessions into a single UI. The browser only talks to the hub.

- **Tailscale auto-discovery.** Enable Tailscale on two machines and they find each other automatically. gmuxd subscribes to tailnet changes and reacts immediately when devices come online. No manual peer configuration, no token exchange. Discovery results are cached so known peers reconnect instantly on restart.
- **Devcontainer auto-discovery.** Add the [gmux devcontainer Feature](https://github.com/gmuxapp/features) to any container and gmuxd discovers it via Docker events. Sessions appear in the sidebar with a topology breadcrumb (`workstation > alpine-dev`).
- **Manual peers.** For machines not on the same tailnet, configure `[[peers]]` in `host.toml` with a URL and token (inline, file, or shell command).
- **Transparent proxying.** Terminal I/O, kill, resume, dismiss, and launch all forward through the hub. The browser doesn't know which sessions are local and which are remote.
- **Fault tolerance.** Each spoke connection is independent. A slow or dead spoke never blocks the hub or other spokes.

### Project hub

Clicking a project name in the sidebar opens a dedicated overview page. Sessions are grouped by host and working directory, with a topology breadcrumb showing the full chain. Per-folder launch buttons route new sessions to the correct machine.

### Home page

The home page shows host cards for every connected machine, with status indicators, session counts, and per-host launch buttons. Offline tailnet devices that look like gmux instances appear as dimmed cards so you know what's out there.

### CLI lifecycle

- **`gmuxd start`** backgrounds via `setsid` + re-exec, logs to `~/.local/state/gmux/gmuxd.log`, waits for health, prints PID.
- **`gmuxd run`** runs in the foreground for systemd, Docker, or debugging.
- **`gmuxd restart`** is an alias for `start` (the old instance is replaced automatically).
- **`gmuxd status`** shows session counts (local/remote/dead), per-peer connection state with error reasons, and the Tailscale URL.
- **`gmuxd stop`**, **`gmuxd auth`**, **`gmuxd remote`**, **`gmuxd version`** unchanged.

### Terminal and configuration

- **Three config files.** `host.toml` (daemon behavior, TOML), `settings.jsonc` (terminal options, keybinds, UI prefs), and `theme.jsonc` (color palette, Windows Terminal theme compatible). All optional, partial configs deep-merge over defaults, settings/theme apply on browser refresh without restarting the daemon.
- **Platform-aware keybinds.** Linux: Ctrl+Alt+T/N/W send the terminal shortcuts the browser steals. Mac: Cmd+Left/Right for Home/End, Cmd+Backspace for delete-to-start, Cmd+K for clear.
- **OSC 52 clipboard.** Terminal apps that write to the clipboard (vim, tmux) now work in the browser.
- **Session replay.** Replaced the ring buffer with a virtual terminal emulator. TUI state, colors, and cursor position are preserved exactly on reconnect.
- **Resize.** The terminal claims viewport dimensions on every session connect. Browser-driven resize uses echo-gated throttling to remove lag.

### Security

- **Unix socket for local IPC.** CLI-to-daemon communication uses `~/.local/state/gmux/gmuxd.sock` (filesystem permissions, no network exposure).
- **Token auth always required on TCP.** No option to disable it.
- **Tailscale identity verification.** The tsnet listener checks every connection against the cryptographic WhoIs identity. The node owner is auto-whitelisted; additional accounts go in the `allow` list.
- **Strict config validation.** Unknown keys, malformed allow entries, and duplicate peer names are rejected at startup.

### Breaking changes from v0.x

- **Config file renamed.** `config.toml` → `host.toml`. The `[network]` section is removed; bind address is controlled by the `GMUXD_LISTEN` environment variable.
- **Keybinds moved.** `keybinds.jsonc` is now a `"keybinds"` array inside `settings.jsonc`.
- **CLI subcommands.** `gmuxd` (bare) prints help. Use `gmuxd start` to background or `gmuxd run` for foreground.
- **TCP auth required.** All TCP connections require a bearer token. The prior unauthenticated localhost exception is removed.
